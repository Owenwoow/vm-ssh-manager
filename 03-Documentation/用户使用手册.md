# VM SSH Manager 用户使用手册

## 1. 用途

为 Windows 11 上 VMware 创建的 Ubuntu、Kali、Debian 等 Linux 虚拟机部署 SSH 公钥，并维护 Windows OpenSSH Config。可选为普通用户配置 `NOPASSWD: ALL`。

## 2. 首次使用

1. 解压总包；CLI 运行 `01-CLI/VM-SSH-CLI.exe`，GUI 运行 `02-GUI/VM-SSH-GUI.exe`。
2. 输入 VM IP、Linux 用户名、首次登录密码、SSH 端口和 Host 别名。
3. 选择现有私钥；若默认 `id_ed25519_vm` 不存在，程序会生成 Ed25519 密钥。
4. 首次连接时核对显示的 SHA256 主机指纹。不要在无法确认指纹来源时接受。
5. 根据需要启用免密 sudo。默认配置会赋予该普通用户完整 root 权限；如果使用 root 账户，程序会自动跳过 sudoers 配置。
6. 完成后执行 `ssh <Host别名>` 连接。

## 3. 密钥

默认路径：`%USERPROFILE%\.ssh\id_ed25519_vm` 和 `.pub`。私钥留在 Windows；只上传 `.pub` 内容。已有文件不会覆盖。若公私钥不完整或不匹配，程序停止并提示，不会自动替换。

## 4. 多台 VM

同一公钥可部署到多台 VM；每台 VM 使用独立 Host 别名。重复初始化不会重复追加相同公钥。Host 别名冲突时需明确选择更新或取消。

## 5. 管理、撤销和删除

CLI 与 GUI 均支持查看/编辑/删除本地 VM Host 记录。编辑本地配置只改 Windows SSH Config 和 VM 元数据，不会连接或修改服务器。删除本地 Host 配置只删除 Windows 本地 Host 块，不会删除服务器公钥。CLI 与 GUI 均支持撤销服务器公钥：只移除 `authorized_keys` 中与所选公钥完全匹配的条目，并在服务器端保留备份。

## 6. 常见问题

- **密码认证失败**：确认 SSH 服务运行、端口正确、目标用户允许密码认证。
- **主机指纹变化**：可能是 VM 重装导致主机密钥变化，也可能存在中间人风险。先通过 VM 控制台确认，再手动处理 `known_hosts`；工具不会自动覆盖旧指纹。
- **sudo 权限不足**：需先由 root、VM 控制台或管理员通道将目标用户加入 sudo 管理组。
- **私钥口令错误**：确认输入的是私钥口令，不是 Linux 登录密码。
- **SSH Config 解析失败**：检查 Windows OpenSSH 是否安装，以及 config 中是否有语法错误。若原文件在全局区段设置了 User、Port、IdentityFile 等项目，或更早的通配 Host 区块设置了冲突值，程序会拒绝生成无效或无法生效的 Host 配置；请先调整原配置顺序。
