# VM SSH Manager 安全说明

## 1. 密码与密钥

- Linux 登录密码、sudo 密码和私钥口令只在当前进程内存中使用，不写入 JSON、日志、SSH Config 或命令参数。
- 私钥不会上传；远端只接收公钥。
- 默认密钥若已存在不会重新生成或覆盖；公私钥缺失/不匹配时停止操作。
- Windows 私钥生成后尝试收紧 ACL，仅授予当前登录用户访问。

## 2. 主机身份

首次连接显示 SHA256 指纹并要求用户确认；已记录的主机密钥不匹配时由 Paramiko 拒绝，不自动替换。

## 3. 远端文件

- 不删除 `authorized_keys` 中其他密钥；安装前备份原文件，写入后设置 600 权限。
- `.ssh` 目录设置 700；拒绝符号链接路径，并在修改前检查目录和 `authorized_keys` 的所有者。
- 撤销公钥时按公钥类型和 Base64 key blob 匹配，保留所有其他条目的原始字节，不因编码问题改写其他行。
- sudoers 不直接改 `/etc/sudoers`；创建独立文件，先运行 `visudo -cf`，再安装为 root:root 0440；验证失败尝试回滚。

## 4. 免密 sudo 风险

`username ALL=(ALL:ALL) NOPASSWD: ALL` 等同于允许该用户无密码取得完整 root 权限。仅建议在个人本地实验 VM 中启用。用户必须明确确认；目标用户需要预先具备 sudo 管理权限。

## 5. 已知限制

- 远程 Linux 需启用 SSH 服务和密码认证以完成首次部署。
- 需要 SFTP 子系统可用。
- 需要目标用户可写自己的家目录；若 `.ssh` 或 `authorized_keys` 所有权异常，工具会报错而不是盲目递归 chown。
- Windows OpenSSH Config 原生解析检查依赖系统 `ssh.exe`。
- Linux 当前开发环境只用于源码检查和单元测试；Windows EXE 必须由 Windows x64 runner 构建和启动验证。
